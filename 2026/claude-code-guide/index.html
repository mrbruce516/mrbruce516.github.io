第一部分：教程

0. 准备与上手

0.1 Claude Code 是什么

Claude Code 是 Anthropic 官方的命令行 AI 编程助手。它不是一个聊天框，而是一个能读你的文件、跑命令、改代码、调工具的智能体（agent）。你在终端里用自然语言提需求，它来动手。

它能做这些事：

  • 看懂一个陌生代码库，回答"这段逻辑在哪、为什么这么写"
  • 写新功能、改 bug、加测试，并自己跑验证
  • 执行 shell 命令、读写文件、按你给的规则工作
  • 通过 MCP 接入外部工具（数据库、API、文档库）

0.2 安装

需要先有 Node.js（建议 18+）。然后全局安装：

1npm install -g @anthropic-ai/claude-code

安装完验证一下：

1claude --version

能看到版本号就成功了。

第一次运行 claude 会引导你登录认证（用 Anthropic 账号或 API key）。按提示走完即可。

0.3 第一次启动

在任意目录输入：

1claude

就进入交互式会话。你会看到一个输入框，光标闪烁，等你说第一句话。

试试这样开场：

1你好，介绍一下你能做什么

或者直接给个任务：

1帮我看一下当前目录有哪些文件，简单解释一下项目结构

它会调用工具去读目录、读文件，然后给你解释。

0.4 怎么提问最有效

Claude Code 不是搜索引擎，给它上下文和目标比给关键词管用得多：

  • 说清做什么："utils.py 里加一个把时间戳转成人类可读日期的函数"
  • 说清为什么："为了在日志里显示更友好的时间"
  • 给出约束：用 Python 标准库，不引第三方包
  • 指向具体文件：用 @文件名 让它直接读，比如 帮我看 @src/auth.py 的登录逻辑

一句话原则：把它当成一个刚入职、还没看过你代码的同事——你交代得越清楚，它做得越准。

1. 基础与工作流

1.1 启动、继续与恢复会话

每次直接敲 claude 是开一个新会话。但你经常想接着上次的活继续干。

1claude -c            # 继续当前目录里最近的一次会话
2claude --continue    # 同上（完整写法）
3claude -r            # 弹出列表，从历史会话里挑一个恢复
4claude --resume      # 同上（完整写法）

-c 是"接着干"，-r 是"翻历史挑一个"。日常用 -c 最多。

也可以给会话起名字，方便以后找：

1claude -n "重构登录模块"     # 启动并命名

1.2 对话循环与上下文

一轮对话里，你说话 → 它思考并调工具 → 给你结果 → 等你下一句。几个影响"上下文"（它记得多少东西）的要点：

引用文件：用 @ 直接喂文件给它，比让它自己找快且准：

1看一下 @package.json，目前依赖了哪些框架

清空重来：聊岔了、上下文乱了，想从干净状态开始：

1/clear

这会清掉当前会话的所有记忆，重新开始（但不退出程序）。

压缩长对话：对话太长时，可以主动让它总结压缩，省 token、聚焦：

1/compact

Claude Code 在对话变长时会自动做上下文管理（总结旧内容、保留要点），你通常不用手动管。/compact 是你想主动控制时用的。

1.3 CLAUDE.md：让它"记住"你的规矩

每个项目都有自己的习惯：代码风格、用什么框架、提交规范。与其每次重复说，不如写进 CLAUDE.md——Claude Code 每次启动会自动读取它，当作长期规则。

两个层级：

文件位置 作用范围 典型内容
项目根目录/CLAUDE.md 仅当前项目 项目架构、技术栈、提交规范、注意事项
~/.claude/CLAUDE.md 所有项目（用户全局） 你的通用偏好：用中文回复、不自动装依赖、注释风格

优先级：项目级会叠加在用户级之上。

快速生成：在一个项目里运行：

1/init

它会扫描代码库，自动生成一份 CLAUDE.md 草稿，你再手动调整。

写什么：好的 CLAUDE.md 不写"做了什么"（代码自己能看出来），而写为什么和约束：

 1# 项目说明
 2
 3## 技术栈
 4- 后端 Python 3.11 + FastAPI
 5- 前端 React 18
 6
 7## 规范
 8- 提交信息用中文
 9- 不自动安装依赖，需要时告诉我手动装
10- 测试用 pytest，改完逻辑要跑一遍

1.4 权限提示怎么应对

Claude Code 要执行"有副作用"的操作（写文件、跑命令）时，默认会先问你。你会看到类似这样的提示：

1Claude wants to run: npm test
2Allow?  (y)es / (n)o / (a)lways allow
  • y —— 这次允许
  • n —— 拒绝，它会换个做法或停下问你
  • a —— 以后这类操作都自动允许（写入允许列表，不再问）

被拒绝不是坏事，说明它在等你确认。如果觉得某个安全操作老被问很烦，选 a 一劳永逸；涉及删除、推送、发布这类不可逆操作的，永远手动确认。

2. Slash 命令与模式

2.1 什么是 Slash 命令

在输入框里以 / 开头的是斜杠命令，用来快速触发功能，不用记 CLI 参数。输入 / 就能看到自动补全列表。最常用的几个：

1/help        # 查看帮助
2/clear       # 清空当前会话上下文
3/compact     # 压缩长对话
4/init        # 为当前项目生成 CLAUDE.md
5/config      # 打开设置面板（主题、模型等）
6/model       # 切换模型
7/cost        # 查看本次会话花了多少 token / 钱
8/review      # 审查当前改动（diff）

2.2 计划模式（Plan Mode）

有些任务你想让它先想清楚再动手，而不是边想边改一通。计划模式就是干这个的。

进入方式：在输入框按 Shift+Tab 切换模式，会在几种模式间轮换；切到"Plan mode"时输入框会有提示。

在计划模式下：

  • 它只读不写：可以看代码、查资料，但不会改文件、不跑有副作用的命令
  • 它会先产出一份计划（要改哪些文件、怎么改、风险在哪），等你确认
  • 你点头后，它才退出计划模式开始执行

什么时候用：复杂改动、不熟悉的代码库、改动面大时。先计划后执行，能少走弯路。

你的全局规则里就写着"复杂任务先进计划模式"——这是好习惯。

2.3 自定义 Slash 命令

如果有些话你反复说（比如"按我们的规范审查这次改动"），可以做成自定义命令。

在项目里建文件 .claude/commands/审查.md（文件名即命令名）：

1请按以下标准审查当前 git 改动：
2- 是否有未处理的异常
3- 命名是否清晰
4- 是否符合项目提交规范
5列出问题并给修改建议。

之后在会话里输入 /审查 就能触发。也可以放用户级目录 ~/.claude/commands/ 让所有项目都能用。

命令文件里可以用 $ARGUMENTS 接收你传入的参数，比如：

1解释 $ARGUMENTS 这个概念的实现，并给出使用示例

然后用 /解释 依赖注入 调用，$ARGUMENTS 会被替换成"依赖注入"。

2.4 用 ! 直接跑 shell 命令

在输入框里以 ! 开头，能直接在当前会话里执行 shell 命令，输出会进到对话上下文里，Claude 能看到：

1! git status
2! ls -la
3! cat config.json

适合你自己想跑个命令、又想让 Claude 看到结果的场景。比开新终端窗口再贴回来方便。

3. 配置与 Hooks

3.1 settings.json：配置文件

Slash 命令是临时操作，配置文件是持久设置。核心文件是 settings.json，分三个层级：

文件 作用域 路径
用户级 所有项目 ~/.claude/settings.json
项目级（团队共享） 当前项目 项目根/.claude/settings.json
项目级（本地私有） 当前项目，不提交 项目根/.claude/settings.local.json

优先级：本地 > 项目 > 用户（越具体的越优先）。

不想手写 JSON？大多数简单设置用 /config 命令在面板里点就行。复杂的（hooks、权限规则）才直接编辑文件。

3.2 权限配置

权限决定哪些工具调用要问、哪些自动放行。在 settings.json 里：

 1{
 2  "permissions": {
 3    "allow": [
 4      "Bash(npm test)",
 5      "Bash(git status)",
 6      "Bash(git diff:*)",
 7      "Read"
 8    ],
 9    "deny": [
10      "Bash(rm -rf:*)"
11    ],
12    "ask": [
13      "Bash(git push:*)"
14    ]
15  }
16}
  • allow —— 自动允许，不问（只读、安全的命令放这）
  • deny —— 一律禁止
  • ask —— 每次都问

写法是 工具名(参数模式)，* 是通配。Read 这种不带括号表示"整个读文件工具都允许"。

小技巧：运行 /fewer-permission-prompts 能扫描你最近的会话，把常用的只读命令自动加进 allow 列表，减少打扰。

3.3 Hooks：让它"自动做某事"

Hooks 是钩子——在特定时机自动触发你写的脚本。比如"每次改完文件自动跑 lint"“每次会话结束给我发个通知”。

主要时机（lifecycle events）：

Hook 触发时机
PreToolUse 调用工具之前（可拦截、改写）
PostToolUse 调用工具之后
UserPromptSubmit 你提交输入时
Stop 一轮回答结束时
SessionStart / SessionEnd 会话开始 / 结束

一个实用例子：每次 Claude 编辑文件后，自动跑 prettier 格式化。在 settings.json 里：

 1{
 2  "hooks": {
 3    "PostToolUse": [
 4      {
 5        "matcher": "Edit|Write",
 6        "hooks": [
 7          {
 8            "type": "command",
 9            "command": "npx prettier --write \"$CLAUDE_FILE_PATHS\" 2>/dev/null || true"
10          }
11        ]
12      }
13    ]
14  }
15}

解读：

  • matcher: "Edit|Write" —— 只在 Edit/Write 工具触发后执行（正则匹配工具名）
  • command —— 实际跑的 shell 命令，$CLAUDE_FILE_PATHS 是 Claude Code 注入的环境变量，含刚改动的文件路径

Hook 脚本的退出码有含义：退出码 0 = 通过，2 = 阻止该操作并把 stderr 反馈给 Claude（可用于拦截危险操作），其它非零 = 报错但不阻止。

3.4 statusline 与环境变量

状态栏（statusline）：终端底部那行显示当前状态的信息。可以在 settings.json 里自定义显示什么：

1{
2  "statusLine": {
3    "type": "command",
4    "command": "echo \"$(git branch --show-current 2>/dev/null) | $(pwd)\""
5  }
6}

它会把命令的输出显示在状态栏。适合放当前分支、目录、模型等信息。

不想手写？运行 /statusline（或让我帮你配）有向导。

常用环境变量（写在 shell 配置如 ~/.zshrc，或 settings.json 的 env 里）：

变量 作用
ANTHROPIC_API_KEY 用 API key 认证
CLAUDE_CODE_MAX_OUTPUT_TOKENS 限制单次输出 token 上限
DISABLE_AUTOUPDATER 设 1 关闭自动更新

4. Subagents 与 MCP

4.1 Subagents（子代理）

当你让 Claude 干一件大而杂的事，让它全装在一个会话里容易乱、容易忘。Subagents 解决这个：把一块独立任务委派给一个子代理去做，做完把结论交回来。

形象理解：你是项目经理，Claude 是你直接对话的助手；遇到需要"专门去查一大片代码"“并行做几件独立的事"时，助手会派几个专员分头去干，各自回来汇报，主线对话不会被一堆细节淹没。

什么时候用：

  • 要在大量文件里找某个模式（搜索型任务，分头找更快）
  • 几个互相独立的任务可以并行（比如同时查三个模块）
  • 主任务上下文已经很满，想把搜索/探索挪出去省空间

日常你不用手动调度，Claude 会自己判断要不要派子代理。你也可以显式要求：“用子代理并行搜索这几个问题”。

4.2 自定义 Agent

就像自定义 slash 命令一样，你可以定义专门角色的子代理，给它固定的身份、工具范围、提示词。放在 .claude/agents/ 目录下，一个 .md 文件一个 agent。

例如 .claude/agents/code-reviewer.md：

 1---
 2name: code-reviewer
 3description: 代码审查专员。审查改动，专注找 bug 和可简化之处。需要审查时使用。
 4tools: Read, Grep, Glob, Bash
 5---
 6
 7你是一名严谨的代码审查员。审查给定的代码改动时：
 8- 优先找正确性 bug（边界条件、空值、资源泄漏）
 9- 其次找可简化、可复用的地方
10- 每条问题给出：文件:行号、问题描述、复现场景、修复建议
11- 不要为了凑数而提无关紧要的风格问题

之后在会话里就能让 Claude 调用这个 reviewer 角色去审查。tools 字段限定它只能用哪些工具（这里只给读和跑命令，不让它改文件，符合"审查员"角色）。

4.3 MCP 是什么

MCP（Model Context Protocol）是一个开放协议，让 Claude Code 能接入外部工具和数据源。你可以理解为"给 Claude 装插件”：

  • 接数据库 → 它能直接查表、写 SQL
  • 接 GitHub → 它能看 issue、提 PR
  • 接你的内部 API / 文档库 → 它能查公司知识

一个 MCP server 就是一个"工具包"，装上后 Claude 就多了这包里的能力。

4.4 添加 MCP server

用 claude mcp add 命令。三种传输方式（transport）：

1# 1. HTTP 方式（远程服务，最常见）
2claude mcp add --transport http sentry https://mcp.sentry.dev/mcp
3
4# 2. stdio 方式（本地启动一个进程）
5claude mcp add my-server -- npx my-mcp-server
6
7# 3. 带环境变量（如需要 API key）
8claude mcp add my-server -e API_KEY=xxx -- npx my-mcp-server

管理命令：

1claude mcp list              # 列出已配置的 MCP server
2claude mcp get <名字>        # 查看某个 server 详情
3claude mcp remove <名字>     # 删除

作用域（-s / --scope）决定配置存哪：

  • local（默认）—— 仅当前项目本地
  • project —— 存进 .mcp.json，团队共享
  • user —— 你所有项目可用
1claude mcp add -s user --transport http sentry https://mcp.sentry.dev/mcp

第一次用某个项目级 MCP server 时，Claude Code 会让你确认是否信任——这是安全机制，防止恶意项目偷偷装工具。

Hooks 时机：

事件 何时触发
PreToolUse 工具调用前（可拦截）
PostToolUse 工具调用后
UserPromptSubmit 用户提交输入时
Stop 一轮回答结束
SessionStart / SessionEnd 会话开始 / 结束

Hook 退出码：0 = 通过；2 = 阻止操作并反馈 stderr；其它非零 = 报错但不阻止。

F. 常见问题 FAQ

Q：怎么换模型？ A：会话里 /model 选，或启动时 claude --model sonnet。别名有 opus/sonnet/haiku 等，也能用完整模型名。

Q：为什么它老让我确认？ A：默认权限模式下，有副作用的操作（写文件、跑命令）都要你点头。觉得烦就把安全的只读命令加进 allow（选 a 自动加，或运行 /fewer-permission-prompts）。删除、推送、发布这类不可逆操作，保持手动确认。

Q：怎么省 token？ A：① 用 @文件 精准喂文件，别让它大海捞针；② 对话长了用 /compact 压缩；③ 任务做完了用 /clear 开新会话，别拖着旧上下文；④ 复杂搜索让它派子代理出去，不占主上下文；⑤ 大而杂的活拆成多个小会话。

Q：它改坏了代码怎么办？ A：所有改动都在工作区，git diff 看改了啥，git checkout 撤回。养成"让它改之前先 commit 或看一眼"的习惯。计划模式（Shift+Tab）能让它先出方案再动手。

Q：配置出问题，连会话都起不来？ A：用 claude --safe-mode 启动，会禁用所有自定义配置（CLAUDE.md、hooks、MCP、自定义命令等），只保留内置功能，方便排查是哪个配置搞坏了。

Q：-p 和交互模式有啥区别？ A：claude -p "提示" 是一次性模式——给它一句话，它输出结果就退出，适合写脚本、接管道。交互模式（直接 claude）是来回对话。排查问题时 -p 的输出也更好接进别的工具。

Q：CLAUDE.md 写多长合适？ A：精简优先。写为什么和约束，别写代码自己能看出来的"做了什么"。太长反而稀释重点、费 token。几十行通常够了。

学完这份指南，你已经能用 Claude Code 完成绝大多数日常工作了。下一步建议：找一个你自己的小项目，从 /init 开始，边用边把项目习惯写进 CLAUDE.md，用着用着就熟了。
