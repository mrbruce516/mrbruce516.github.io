Claude Code 权限模式详解

权限模式决定 Claude 在执行文件编辑、shell 命令、网络请求前"停下来问你"的频率。所有模式都以你的权限规则（allow / ask / deny）为基线，模式只改变基线的松紧。

本文是 Claude Code 命令行活用指南 的姊妹篇，专讲权限这一块。

总览

模式（配置值） CLI 状态栏标签 无需提示即可执行 适用场景
default Manual 仅读取 入门、敏感操作
acceptEdits ⏵⏵ accept edits on 读取、文件编辑、常见文件系统命令 边改边 review 的迭代
plan ⏸ plan mode on 读取，外加（auto 可用时）分类器批准的命令 动手前先探查、出方案
auto ⏵⏵ auto mode on 几乎一切，带后台分类器安全检查 长任务、减少提示疲劳
dontAsk ⏵⏵ don't ask on 仅预批准工具 锁定的 CI、脚本
bypassPermissions ⏵⏵ bypass permissions on 一切（含受保护路径） 仅限隔离容器/VM

命名差异：审查每个动作的模式在 CLI、claude --help、IDE 中都叫 Manual，但配置值是 default。CLI 接受 manual 作为别名。

切换方式（通用）

  • 会话中：按 Shift+Tab 循环 default → acceptEdits → plan，再回到 default。auto、bypassPermissions 在满足条件时插入循环。Windows 上若 VT 输入未启用，改用 Alt+M。
  • 单次提示进 plan：在提示前加 /plan。
  • 启动时：claude --permission-mode <mode>（同样支持 -p 非交互运行）。
  • 持久默认：settings 文件中设 permissions.defaultMode。

auto、bypassPermissions、dontAsk 不在默认循环里：

  • auto：账号满足要求时才出现在循环中。
  • bypassPermissions：需用 --permission-mode bypassPermissions、--dangerously-skip-permissions 启动，之后才进入循环；普通会话启动后无法切进去。
  • dontAsk：永不进入循环，只能用 --permission-mode dontAsk 启动。

1. default（默认 / Manual 模式）

  • 触发：默认即此模式；Shift+Tab 循环到它；claude --permission-mode default（或 manual）。
  • 能做：读取文件、运行内置只读 Bash 命令，无需提示。
  • 不能做：任何写文件、非只读 shell 命令、网络请求都要先问你。
  • 适用：刚入门、做敏感操作、对方向还不确定时，逐个审查每个动作。
  • 注意：受保护路径写入仍会提示。

2. acceptEdits（自动接受编辑模式）

  • 触发：Shift+Tab 从 Manual 按一次进入；claude --permission-mode acceptEdits；或 settings defaultMode: "acceptEdits"。
  • 能做（免提示）：
    • 在工作目录（及 additionalDirectories）内创建/编辑文件；
    • 常见文件系统命令：mkdir、touch、rm、rmdir、mv、cp、sed；带安全环境变量前缀（如 LANG=C、NO_COLOR=1）或进程包装（timeout、nice、nohup）也免提示；
    • 启用 PowerShell 工具时，Set-Content、Add-Content、Clear-Content、Remove-Item 及常见别名同样免提示。
  • 不能做（仍提示）：工作目录外的路径、受保护路径写入、除内置只读集外的其他 Bash 命令。
  • 适用：你愿意事后用编辑器或 git diff 审查改动，而不是逐条批准内联编辑。
  • 注意：仅限工作目录内；范围外和受保护路径仍提示。

3. plan（计划模式）

  • 触发：Shift+Tab 循环到；提示前加 /plan；claude --permission-mode plan；或 settings defaultMode: "plan"。再按 Shift+Tab 可不批准计划直接退出 plan。
  • 能做：读文件、跑命令探查代码库、写出计划方案——但不编辑源码。
  • 不能做：编辑源码（在有 bypass 的会话除外）。命令方面：
    • 当 auto 模式可用且 useAutoModeDuringPlan 开启（默认开）时，分类器审查 shell 命令：批准的运行，拒绝的阻断；
    • 否则，除内置只读集外的命令都要提示批准；
    • 有 bypass 权限的会话跳过这两条路径。
  • 计划审批：Claude 呈现计划后可选：
    • Yes, and use auto mode（auto 不可用时显示 “Yes, auto-accept edits”；bypass 会话显示 “Yes, and bypass permissions”）；
    • Yes, manually approve edits；
    • No, refine with Ultraplan on Claude Code on the web（送到浏览器审阅）；
    • No, keep planning。
    • Ctrl+G 可在默认文本编辑器里直接改写计划再继续。
  • 适用：动手前先理解代码库、出方案再执行。
  • 注意：批准计划即退出 plan，切到对应模式开始编辑；想再规划要重新切回 plan。

设为项目默认（.claude/settings.json）：

1{ "permissions": { "defaultMode": "plan" } }

4. auto（自动模式 / 全自动带安全检查）

这是"全自动"的推荐方式——不是无脑放行，而是由独立分类器模型在执行前审查每个动作，阻断越界行为。

  • 触发：满足账号要求时出现在 Shift+Tab 循环中；claude --permission-mode auto；settings defaultMode: "auto"（仅用户/托管 settings 生效，会忽略项目/本地 settings 里的 auto，防止仓库自行授予 auto）。
  • 能做：几乎一切，分类器判定安全即放行。默认放行：工作目录内本地文件操作、按锁文件/清单装依赖、读 .env 并把凭据发给匹配的 API、只读 HTTP、push 到当前仓库任意分支、创建符合请求的 PR 等。
  • 不能做（分类器默认阻断）：下载并执行代码（curl | bash）、向外部端点发敏感数据、生产部署/迁移、云存储批量删除、授予 IAM/repo 权限、改共享基础设施、不可逆销毁会话前已存在文件、force push、git reset --hard/git checkout -- ./git restore ./git clean -fd/git stash drop/git stash clear、git commit --amend（HEAD 非本会话创建，或已 push）、terraform/pulumi/cdk/terragrunt destroy 及销毁性 apply；还阻断写 secret manager、改 DNS/TLS、合并无人批准的 PR、关 CI 检查、改生产 feature flag、对受保护 IaC 施变更、开反向隧道、打印活凭据、绕过内部包仓库装包、用 --insecure 等解除安全护栏的命令、启动无沙箱无人审批的自治 agent 循环等。rm -rf / 和 rm -rf ~（含命令/进程替换形式）由分类器判定。
  • 边界：你在对话里声明的边界（如"别 push"“部署前等我 review”）会被分类器当作阻断信号，直到你后续消息解除。但边界不存为规则，上下文压缩可能丢失——要硬保证就加 deny 规则。
  • 回退：连续被阻断 3 次或累计 20 次，auto 暂停并恢复提示；批准被提示的动作即恢复 auto。阈值不可配。非交互 -p 模式下重复阻断会中止会话。
  • 成本/延迟：分类器默认跑在 Claude Sonnet 5，而非你的 /model；调用计入 token 用量。读取和工作目录内编辑（非受保护路径）跳过分类器，开销主要来自 shell 命令和网络。
  • 账号要求：所有套餐；Team/Enterprise 默认开（管理员可用 permissions.disableAutoMode: "disable" 关闭）；模型需 Opus 4.6+/Sonnet 4.6+/Fable 5。
  • 适用：长任务、信任大方向但想要后台安全网。官方明确：auto 减少提示但不保证安全，不能替代对敏感操作的审查。
  • 注意：进入 auto 时，宽泛的代码执行 allow 规则（如 Bash(*)、Bash(python*)、包管理器 run、Agent allow）会被丢弃，离开时恢复；窄规则（如 Bash(npm test)）保留。

查看完整默认规则：claude auto-mode defaults（输出 JSON）。

5. dontAsk（只允许预批准工具）

  • 触发：claude --permission-mode dontAsk（永不进入 Shift+Tab 循环）。
  • 能做：仅匹配 permissions.allow 规则的动作、内置只读 Bash 命令、被 PreToolUse hook 批准的调用。会话永不等待输入。
  • 不能做：其余一切自动拒绝；显式 ask 规则匹配的调用被拒绝（而非提示）；内置 AskUserQuestion 工具被拒；组织设为 ask 的连接器工具被拒；MCP 工具标记 requiresUserInteraction 的也被拒。
  • 适用：CI 流水线、受限环境，你已预先精确设定 Claude 能做什么。
  • 注意：云会话（Claude Code on the web）忽略 defaultMode: "dontAsk"。

6. bypassPermissions（跳过所有检查）

  • 触发：claude --permission-mode bypassPermissions，或等价的 --dangerously-skip-permissions，或 settings defaultMode: "bypassPermissions"，或 --allow-dangerously-skip-permissions（仅加入循环不激活）。一旦普通会话启动后无法切进去。
  • 能做：一切立即执行，包括写入受保护路径。
  • 仍会提示（即使此模式）：
    • 显式 ask 规则、组织设为 ask 的连接器工具、requiresUserInteraction 标记的 MCP 工具；
    • 针对 / 和 ~ 的删除（如 rm -rf /、rm -rf ~）作为"熔断器"；含 $(...)、反引号、<(...) 的命令也触发，无论删除在替换内还是同命令别处。
  • 安全限制：
    • 首次交互启动会弹警告对话框要求你承担责任，接受后存到用户 settings（仅一次）；拒绝则退出；非交互模式不弹窗；--bg 后台会话在你交互接受前会被拒绝；
    • Linux/macOS 上以 root 或 sudo 运行时拒绝启动（识别到的沙箱内自动跳过此检查），建议用 dev container 配置以非 root 用户跑。
  • 适用：仅限隔离环境——容器、VM、无网络的 dev container，Claude 伤不到宿主。
  • 注意：官方警告此模式对 prompt 注入或意外动作无任何防护。要"少提示但有安全网"请用 auto 而非 bypass。管理员可用 permissions.disableBypassPermissionsMode: "disable" 在托管 settings 中禁用。

受保护路径（所有模式通用）

写入下列路径除 bypassPermissions（及有 bypass 的 plan 会话）外永不自动批准，防止破坏仓库状态和 Claude 自身配置。permissions.allow 规则也不能预批准这些写入（安全检查在 allow 规则之前执行）。

各模式对受保护路径写入的处理：

模式 受保护路径写入
default、acceptEdits 提示
plan 提示；有 bypass 的会话允许；否则 auto 可用时走分类器
auto 走分类器
dontAsk 拒绝
bypassPermissions 允许

受保护目录：.git、.config/git、.vscode、.idea、.husky、.cargo、.devcontainer、.yarn、.mvn、.claude（除 .claude/worktrees）。

受保护文件：.gitconfig、.gitmodules；shell 配置（.bashrc/.zshrc/.profile/.envrc 等）；包管理配置（.npmrc/.yarnrc/.pnp.cjs/bunfig.toml 等）；.bazelrc 等；.pre-commit-config.yaml/lefthook.yml；gradle-wrapper.properties/maven-wrapper.properties；.devcontainer.json；.ripgreprc/pyrightconfig.json；.mcp.json/.claude.json。

在提示模式下，.claude/ 写入的提示会提供 “Yes, and allow Claude to edit its own settings for this session”，一次批准后续该会话内 .claude/ 写入不再提示。

实用提示

  • “复杂任务先进计划模式”——可直接把项目默认设为 plan（.claude/settings.json 的 defaultMode: "plan"），或继续用 /plan 前缀单次进入。
  • 想少打字但仍要安全网，优先用 auto 而非 bypass。/doctor 会在支持的 provider 上建议把 auto 设为用户默认。
  • 查看当前权限规则与最近拒绝：会话内 /permissions（最近拒绝的可在 “Recently denied” 标签按 r 重试）。
  • 调整权限规则（如预批准常用只读命令减少提示），可用 /update-config 或 /fewer-permission-prompts。
